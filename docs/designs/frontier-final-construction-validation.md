# Construction-first milestones: final validation and limits

The six milestones deliver the supported implementation and its validation
receipts. This records implementation acceptance separately from kernel
compilation and fixed-protocol capacity. It does **not** claim an all-green
PTOAS suite, device execution, or completion of unrestricted Sections 5–8.
The [machine-readable receipt](frontier-final-construction-validation.json)
pins the campaigns, repaired reruns and remaining failures. Earlier measurements
remain in the [historical evidence log](frontier-family-pipeline-history.md).

## Ordered production campaign

The final production campaign used the pinned 227-input implementation after
`480665618`, with one CPU, a 4-GiB address-space ceiling and per-stage watchdogs.
It ran in the required order:

| Corpus | Logical analysis/insertion | Physical allocation | Generated C++ |
|---|---:|---:|---:|
| Primary PyPTO-lib modules | 49/49 | 49/49 | Not requested |
| PyPTO captures | 22/22 | 22/22 | Not requested |
| Prepared kernels | 11/11 | 8/11 | 8/11 |

The other three prepared allocation outcomes are distinct: default prefill lacks
a supported finite/uniform export; decode lacks a certified regional lane
assignment; Delta's sufficient fresh-invocation prefix placement requires more
than six IDs, without a reusable allocation export. The experimental prefill
typed export is a separate successful investigation and remains opt-in.
The fresh-placement refusal is not a checked minimum. The checked protocol
witnesses in M3 establish their own bounds under explicit command causality.

Per-case receipts retain commands, input hashes, logical/generated-control
metrics, allocation outcomes and C++ emission separately under
`.local/milestone-loop/final-construction-production/`. C++ generation does not
establish device-kernel compilation. No device compiler or device execution was
run. Later changes affect only test helpers and the test executable; the planner,
emitter and compiler library used by this campaign remain unchanged.

The immutable broad gate completed **234 tests: 217 PASS, 16 FAIL, one TIMEOUT**
in 734.99 seconds, serially with a 120-second lit watchdog and the same 4-GiB
ceiling. This is the original result, not a score rewritten after repairs.

Six failing full tests subsequently pass in separately pinned focused gates:

| `sync_late_local_barriers` | Check every raw hazard against exact PIPE_S protection or actual causal reachability; do not invent hardware C→I edges. All 72 scalar/vector traces pass, retaining nonvacuous vector late barriers. |

Each repair has independent correctness and architecture acceptance and its own

existing binaries. No aggregate intensive execution exceeded two workers.
