## Gates and execution

Each batch includes semantic/scaling tests, production callers, deletion criteria
and both reviews. Construction acceptance requires independent equivalence,
structural work counts and serial paired timings; reduced preparation is
insufficient when materialization reconstructs the same work. Selection must
construct no later form after explicit success, avoid repeated walks for identical
requests, and reconstruct only documented dependencies on capability upgrades.
Record reasons, failure stage, reused outputs and unused construction; separate
audit measurements from production.

Allocation requires a certified assignment or checked bound under explicit
protocol premises. Lowering requires equivalent unfolded communications and
legal reuse across both routes, with smaller total constructed/live control
where claimed. Record renaming must not grow dispatch. Child composition requires
independent pending-state and command-graph checks, sound summaries and no hidden
increase in ordering at import boundaries.

Scaling covers threshold cells, unaffected DAG branches, noncommuting matrices,
stable/nonstable powers, repeated capability requests, provenance renaming,
skipped/nonunit visits, zero/partial invocations and simultaneous commands.
Use incremental builds and at most two aggregate intensive workers. Run focused
checks after meaningful changes and broader checks at batch gates. Comparable
paired timings run serially without overlapping builds. Commit only after both
reviews accept the batch; never push automatically.
