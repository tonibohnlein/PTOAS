# Exact one-coordinate handoff extrema

The optional arithmetic handoff path constructs first-source and last-target
selectors from existing one-coordinate witnesses. It avoids constructing the
pairwise endpoint order, projecting that order, then subtracting it from the
original support. Unsupported cases keep that original exact construction;
this is a representation optimization, not an admission cutoff or an allocation
certificate by itself. Actual prefill export and capacity are separate outcomes.

## Qualification and mechanism

Every support key must have one endpoint coordinate and the existing parameter
schema. Within a parameter-residue group, endpoint sites must agree, including
empty-key inventories. Each nonempty conjunction must have a normalized lower
bound on that exact endpoint quotient for a minimum, or an upper bound for a
maximum. Bounds on parameter columns do not satisfy this requirement. Original
endpoint and parameter residues remain part of the qualification.

For each qualified conjunction, the existing integer witness construction keeps
parameters and eliminates only the endpoint quotient. Its candidate family
contains the minimum for every fixed feasible parameter valuation: an equality
has its unique integral witness; finite unary-lattice or strip enumeration covers
all possible values; otherwise the existing Cooper construction enumerates a
full congruence period above every lower endpoint. The least feasible value lies
within that period of the maximal lower endpoint. No first-witness ordering
assumption is used.

Maximum construction reflects only the endpoint quotient, obtains the same
minimum candidate family, then negates each quotient witness back. Original
residues are retained. Candidate domains preserve exact feasibility and quotient
integrality through the existing substitution divisibility conditions.

All candidates for a site and parameter-residue group compete, including
candidates with different endpoint residues. Full original coordinates are
`period * numerator / denominator + residue`, with a positive denominator and
exact integral quotient on the candidate domain. Positive-denominator cross
multiplication therefore expresses strict improvement exactly. Subtracting the
union of feasible strictly better candidate domains uses only parameter columns.
Ties retain equal tagged coordinates. The resulting selector covers exactly the
global extremum of the original support, including overlapping or disjoint pieces.

## Ownership, work and validation boundary

The helper retains no callbacks, original operations, mutable plan or speculative
expression IDs. Optional construction failure leaves the original extremum path
available. The original mathematical kernels and the private baseline test seam
remain intact.

Existing exclusive extrema, projection and difference scopes include the new
work. Bounded aggregate diagnostics count qualification, witnesses, candidates,
comparisons, selected pieces and per-attempt parameter-difference work, including
unsuccessful attempts. They add fields to the existing handoff-construction row
rather than growing the ledger once per family. These structural counts do not
establish wall-time or memory improvement.

Source controls compare the candidate with an independent raw-point oracle,
including every enabled selector piece, equality, unary and strip enumeration,
Cooper residues, signed coordinates, parameter contexts, overlap and disjointness,
and empty domains. The simple overlapping case also checks the original algorithm;
unsupported nested/unbounded/mixed-site cases check the retained original path. Profile-on/off
controls retain the same result and work. A 4/8/16-piece exact-point family checks
both algorithms' extrema and fewer candidate joins/projections, while counting
every new parameter difference. Compilation, focused execution and a
fresh actual-prefill probe remain required; no successful export or measured
speedup is asserted by this source receipt.
