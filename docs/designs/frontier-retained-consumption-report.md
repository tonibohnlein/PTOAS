Whole-loop child qualification retains mathematics and a preparation callback.
Legacy bounded preparation still constructs detached SSA. It is instantiated
fresh inside the insertion transaction, rather than retained across destruction
of the original function body. A regression exposed that ownership hazard during
development; the completed whole-loop import test covers the replacement step.
This is not a new scalar emitter, and it does not eliminate legacy preparation
work on fresh instantiation.

Matching closure, consumption-before-republication, and payload completion
remain separate facts. The parent imports conservative payload summaries and
keeps its SCC-selected boundary completions. Enclosing counted-loop coordinates
distinguish logical visits. An ALL barrier is not treated as consuming an
unmatched notification.

Resource checking propagates pending child owners over the supplied CFG. Its
work is charged in resource-state visits; the richer proof is not claimed to
have the previous two-state bound. The default local assignments can still
choose overlapping IDs. This change exploits disjoint supplied assignments; it
does not search for new child assignments. A failed provisional resource import
still retries the existing primitive route once.

## Representation selection

The mixed absolute/periodic fixture retains a sequence recipe costing 207
construction operations and an independently qualified arithmetic recipe costing
89. A subsequent capability request selects the cheaper arithmetic owner. An
identical request thereafter returns the retained selection without another
comparison or producer construction. The counter is checked against actual
materialization by the shared preparation tests.

Canonical producer caches own arithmetic/bounded/varying exports. Selection
reads those caches rather than assuming that the request adapter owns all
capabilities. No producer or missing export is constructed for the comparison.

This is a construction-work metric, not a hardware latency model. A cold request
with only one completed alternative still follows ordinary dispatch. In
particular, the historical cold 125-to-300 arithmetic regression is not claimed
universally repaired by warming every candidate. Existing exact-key selections
also remain stable when later evidence appears.

## Arithmetic sharing and indexing

Four retained relation inventories use shared storage across result wrappers and
capability masks. Construction mutates through an explicit copy-on-write borrow.
Required-order continuations and DBM conversion remain the existing algorithms.
The copy counters measure relation entries and piece objects copied at this
boundary; they do not measure every scratch relation or deep allocator byte.

The regional index is keyed by source site, target site, and event kinds. Its
retained relation handle pins indexed entries. Each query inspects only the
corresponding residue alternatives. Native same-pipe shortcuts remain intact.
Tests check repeated export storage identity, independent mutation, index
construction once, relevant-key inspection, and the existing relation oracles.
Query diagnostics update one owner-local aggregate ledger record, including
saturating query/index/inspection counters; profiling does not retain one record
per reachability call.

## Opt-in down-projection: order improves, control grows

With `normalize-two-trip-loops=true`, the new import reduces static ALL sites from 13 to 7 relative to normalization
alone, while increasing static SET/WAIT sites from 15/15 to 191/191. These are
different valid protocols; fewer static commands is not the primary objective.

For the checked K=17 execution, 239 payloads are retained. Extra
completion-to-start pairs fall from 629 to 16; executed barriers fall from 45 to
6. Notifications increase from 85 to 191 matched pairs. Evaluated arithmetic
increases from 343 to 86,628. This is a substantial control-code regression and
must not be described as a runtime speedup. It exposes the existing bounded
endpoint construction now preserved inside fallback.

All eight checked executions have no missing required completion-to-start
pairs and pass physical reuse checks. Split and combined output have identical
physical command arrays. These include empty, zero-K, short, even, tail and
K=17 cases. The independent
all-conflict/native closure uses the exported concrete effects; it is not an
independent hardware-effects model.

## Validation status

The focused seven-test gate passes, including whole-loop and nested import,
disjoint palette rollback, threaded combined output, arithmetic oracles,
retained selection, and scalar construction-count parity.

The first 347-test gate passed 337 tests. It retained the three legacy InsertSync
failures and exposed six tests whose original-coordinate representation
assumptions conflict with default two-trip normalization, plus a bounded-emission
fixture failure. Recompiling that test object made its unchanged semantic checks
pass; no production or expectation change was used to repair that case. The
first receipt remains recorded separately, and qualification uses the rebuilt
full gate.

Default-enabled normalization caused both `gate_up_proj` corpus variants to
exceed the unchanged 120-second limit. A sampled stack localizes work to machine
footprint relation extraction through `finiteArithmeticRegion()` and repeated
composition, before completion-child import. Disabling normalization completed
the diagnostic input in approximately 0.36 seconds. Trying the compact repeated
adapter first did not resolve it; that experimental source change was removed.

Normalization therefore remains explicitly opt-in. The original representation
tests retain their original default commands and assertions. The dedicated
two-trip and down-projection checks enable it explicitly. This preserves the
default production acceptance scope; it does not claim automatic default
improvement for down-projection or repair of gate-up's normalized representation.
The interrupted default-enabled campaigns remain local evidence, not a complete
acceptance receipt. No timeout limit has changed.

The final default primary campaign passes **49/49 logical, 49/49 six-ID split
allocation and 49/49 combined-output compilations**. Against the immediate
`2df046db8` baseline, 39 physical outputs are byte-identical and the remaining ten
differ only in recognition diagnostics. Of the logical outputs, 31 are
byte-identical, ten differ only in recognition diagnostics, and eight additionally
encode constant allocation maps as zero-term tuple rules. Removing exactly those
metadata changes establishes unchanged logical bodies. This does not assert

The dedicated completion run uses two available CPUs and compares serial and
