# Sections 5–6: regional fallback and reusable certificates

Baseline: `4710959d9`. Status: M1–M4 accepted; M5 remains open.

The implementation preserves exact minimum demands, original cuts, matching and
established realization guarantees on exact paths. Completion fallback reports
coverage and possible added order. An exact mathematical answer with a missing
export never authorizes weakening that answer.

## Reviewed implementation sequence

1. **Regional completion ownership:** separate proper-region pending summaries
   from whole-invocation completion; import eligible retained inline children and
   existing qualified calls atomically; reuse the SCC engine and module staging.
2. **Completion inputs and guarantees:** hierarchy-wide proved storage classes,
   qualified forward scalar readiness, explicit conservative guarantees and
   optional symbolic payload-order loss bounds.
3. **Periodic/repeated certificates:** preserve modular boundary selectors and
   numerical indices; qualify supplied phases without arbitrary period search;
   close the phased-repeat watchdog using its independent oracle.
4. **Bounded lifetimes:** share rotating normalization, derive collective refresh
   gaps from guaranteed writers, retain one certified window across exports.
5. **Arithmetic construction contracts:** retain normalized whole-primitive
   certificates and report actual projection/subtraction/export strategy costs;
   preserve cheap representations through qualifying composition.

Each milestone includes production callers, semantic and structural scaling
checks, a deletion ledger, two independent reviews and one accepted commit before
starting the next. Reuse incremental builds; at most two aggregate heavy workers.
Do not push automatically. The final gate includes Frontier tests and the 49
primary PyPTO-lib modules; report the broader legacy gate separately. Three serial
interleaved timing pairs measure affected fixtures; neutral results remain valid.

## Scope decisions

Use existing Empty, CompletedExit and ClosedDescendants resource contracts. New
pending children owning local events, coordinator protocols, protocol synthesis,
runtime dependence analysis and device qualification are excluded. Start with
the qualified A3 single-core ALL-barrier protocol. An ALL barrier does not consume
outstanding notifications. Unsupported history, resources or readiness remain
unmet capabilities. No new public pass, solver or arbitrary admission cutoff.

Proper regions are contiguous original structural intervals; macro envelopes are
indivisible. Empty and zero-trip children pass incoming pending work through.
While summaries include the final false condition visit. Child effects, matching
closure and completed payloads are separate facts. Imported exact code is retained,
not reconstructed by the conservative solver.

## M1 implementation and deletion ledger

Implemented and accepted by architecture and compiler-correctness reviewers.
The [M1 receipt](frontier-sections56-m1-results.json) records source hashes and tests.

The completion graph accepts contiguous original roots and qualified inline child
implementations. Proper regions retain pending suffixes and transparency; only a
whole invocation adds its terminal drain. Proper owners are append-only fragments,
not standalone function transformations. A whole owner stages their retained
recipes and boundary completions in the existing module transaction.

Inline finite import currently admits no-notification recipes: exact local
barriers and their certified scalar preparation. Existing call imports retain
Empty, CompletedExit and ClosedDescendants contracts. An eventful inline result
without supported closure evidence remains unselected; its mathematical result
is retained, and the parent can descend through that candidate. Once a child is
accepted, failed revalidation aborts the parent transaction. Neither an exact
demand result nor a visible ALL establishes notification closure.

A source snapshot validates the shared input/index association once, retains the
original function/module identity and immutable phase facts, and is shared across
session scopes. Staging validates each distinct source and imported callee once.
Scope inspection reports actual operation/phase visits and graph vertices.

The regional straight-line adapter already retains a finite owner inside its
singleton sequence result. Fallback retrieves that owner; it does not reconstruct
finite mathematics or add a separate regional finite adapter.

## M2 implementation and deletion ledger

Implemented and accepted by architecture and compiler-correctness reviewers.
The [M2 receipt](frontier-sections56-m2-results.json) records source hashes and evidence.

Completion source snapshots now own one deterministic storage-class universe for
all proper scopes. Classes distinguish proved address spaces and disjoint local
physical reservations. Overlapping or adjacent reservations are merged; every
address-table alternative participates. Missing addresses, zero/overflowing
extents and lost provenance conservatively cover the entire space. Unknown
spaces cover all classes. GM remains coarse. Unknown memberships retain ranges,
not copied class inventories. Empty and call-only functions have at least one
class. Dense graph summaries still cost O(vertices × classes); this is not an
end-to-end linearity claim.

Finite inline effects use that same classifier. Proper completion children share
the full input's deterministic numbering, including across source snapshots.
Callee exports remain deliberately coarse: collapse and lift A, E and S separately
and preserve transparency. Callee-local reservations never become caller class
identities without argument-substitution evidence.

A qualified scalar prerequisite stays within one original block and visit.
Completion precedes the earliest direct scalar use, including intermediate pure
arithmetic; the final payload consumer is not used as a substitute for that cut.
Control, carried, escaping and externally sourced obligations remain unavailable.
An accepted atomic child hiding a mandatory cut is refused. Readiness discovery
reports operation and use visits separately. Integration tests inject an
asynchronous contract into test-owned input phases; production tgetval remains
synchronous and its ISA semantics are unchanged.

The result reports covering modeled order, SCC placement, actual class count,
readiness cuts, retained inline children, zero parent event IDs and separate
matching/payload-completion semantics. The optional realized-order loss bound
remains explicitly unavailable, never zero. Existing child-resource restrictions
remain unchanged.

| One-class primitive effect assembly | Snapshot-owned CompletionStorage | Removed |
| Direct copy of callee class numbering | Coarse A/E/S collapse and caller lift | Removed |
| Blanket nonnative scalar-result refusal | Same-block first-use readiness certificate and mandatory SCC entries | Unsupported forms still explicitly refused |

M2 qualification passes 12/12 focused tests, including storage overlap oracles,

1.013, 1.019 and 0.998 for disjoint256, wildcard256 and while control. Disjoint256

to two. These are conservative-order improvements, not device-speed measurements.

## M3 implementation and qualification

The existing regional storage certificate now separates three capabilities:
complete physical support envelopes, uniform selector partitions of requested
ranges, and exact byte-selector queries. Envelopes may contain holes; neither an
envelope nor a partition establishes access membership. All four boundary
selector sets and their exact guards must be uniform within a certified atom.

Rotating storage derives these capabilities from its admitted canonical cells and
checked bank geometry. Requested partitions inspect intersecting banks; complete
support uses one envelope per family. No joint address period is enumerated.
Unsupported residual storage supplies neither new capability. Sequence and
invariant repetition retain geometry under their existing physical-map premises;
coordinate transformations do not substitute for a physical invariance proof.
Arena, access-model and alias context must match before evidence is forwarded.

Finite crossing projection refines overlapping counterpart ranges together and
keeps symbolic effects and pair-specific coverage. A partial requested projection
never becomes a whole-region uniform-effects certificate. Ordinary repetition
still accepts materialized original ranges; otherwise complete regional support
can supply the crossing footprint. Both paths use the same exact selectors and
retain original effect-extrema, invariance and alias checks.

| Previous conversion | Replacement | Compatibility behavior |
|---|---|---|
| Every requested physical byte becomes a crossing atom | Certified uniform cuts, then exact selector queries | Bounded per-byte adapter remains when no uniform proof exists |
| Original effect ranges must be materialized before repetition | Original ranges or complete regional support envelopes | Missing complete support remains unavailable |
| Geometry discarded across coordinate-only composition | Scoped certificate forwarding and common refinement | Address-changing or unsupported residual cases refuse |

The existing regional atom limit remains in force. Large complete interfaces can
still exceed it; a compact support envelope is not a promise that all its atoms
can be materialized economically. Inspected partition work, retained atoms,
represented bytes and relational compositions are reported separately.

Canonical nested loops with invariant physical banks now try the existing guarded
periodic exporter before arithmetic. Only certified geometry parameters are
substituted; original coordinates, symbolic trip bounds and cuts survive. Moving
outer banks retain the established canonical/phase path: the new guarded-child
composition does not yet supply its allocation lifting. A mathematical regional
success does not imply that lazy physical allocation can retry another protocol.
No allocation certificate is transferred between different logical plans.

Initial representation selection shares the existing repeated-allocation
crossing-shape check: the current adapter requires unit displacement. When all
nonunit crossings have one supplied displacement, composition may prefer the
existing phase representation before publishing the selected owner. Mixed nonunit crossing periods retain the compact representation. The phase
recognizer can still discover additional storage periods; its existing
qualification and limits govern that work. Failed phase construction leaves the incumbent
available. This is a capability/cost heuristic, not an allocation attempt or
capacity proof. Mathematical requests can pay this phase qualification cost:
later endpoint requests otherwise reuse the already-ready mathematical owner and
do not revisit representation choice. Physical assignment remains separately
certified for the selected whole plan.

M3 qualification passes 17/17 focused tests. The repeated fixture now completes
its 17 general traces, 43 phase/overlap/writer cases and 21 physical allocation
checks under unchanged interpreter limits. Required and emitted payload closures,
logical matching and consumption-before-republication are checked independently.
The scalar oracle adds target-protected edges only for actual conflicting scalar
effects, never for every pair of scalar operations. The partition oracle checks
all bytes in supplied finite domains, holes and noncoprime orbits, foreign arena/
model/alias contexts and huge bank geometry with bounded inspected work.

| Additional replaced orchestration | Replacement | Remaining limitation |
|---|---|---|
| Unconditional arithmetic canonical nested loop | Optional guarded export for invariant physical banks | Moving-bank guarded canonical lifting is not added |
| Repeated insertion's private crossing-shape check | One shared allocation-interface shape predicate | Unit shape does not guarantee an assignment |
| First regional success despite a known missing crossing export | Single-nonunit-period phase preference before ownership publication | General physical-request-driven retry remains separate |

The [M3 receipt](frontier-sections56-m3-results.json) records both reviewer
acceptances, source hashes and the final gate. Three serial interleaved timing
pairs give an original-fixture candidate/baseline median ratio of 0.997. The
two-phase fixture's baseline hit 20 seconds in all three pairs; candidate runs
completed around 0.040 seconds. Those baseline measurements are censored, so no
finite speedup ratio is claimed. No device measurement was performed.

## M4 implementation and qualification

Rotating generator extraction and bounded refresh qualification now share one
geometry/protection normalizer. It retains supplied fragment order, validates
family moduli/strides and duplicate protection, and computes orbit phases without
constructing hazard generators or enumerating slots. Generator extraction keeps
its existing consolidation and circular sweeps after normalization.

Refresh qualification groups guaranteed writer phases by family, atom and orbit.
The largest circular gap in each union bounds refresh from any starting visit;
the final bound includes the supplied prerequisite span. Possible writers do not
establish guaranteed refresh. Complementary guards count only through the
existing producer's exact-map coverage proof. Read-only orbits require no refresh;
an uncovered writable orbit still refuses. This changes a sufficient window
bound, not activity, endpoint availability, history or the physical-ID protocol.

The existing bounded owner retains one window for subsequent requests and exports.
No new runtime evaluator or separate bounded emitter is introduced. The new
physical-orbit oracle enumerates slots and start visits independently, and
compares the shorter window's source covers with the older sufficient window.
Production tests retain dynamically changing guards and independent command
closure checks. Normalization scaling counts supplied fragments and families for
64–4,096 fragments over a 2^48-slot domain; it does not expand that domain.

| Previous work | Replacement | Removal status |
|---|---|---|
| Refresh calls full rotating generator extraction only for validation | Shared original-order normalization | Unused generator construction removed |
| Maximum individual writer period | Maximum gap of guaranteed writer phase union | Old bound construction removed; prerequisites remain |
| Repeated duplicate-protection validation during consolidation | Shared normalizer validates the exact key | Redundant production rejection removed |

Both reviewers accepted M4 after 19/19 focused tests and the independent
refresh/rank oracle passed. The [M4 receipt](frontier-sections56-m4-results.json)
records 13,640 physical-orbit cases and the production command checks. Three
interleaved short fixture runs have a median paired ratio of 0.646; this is a
fixture-local observation including process/interpreter overhead, not an
end-to-end compiler or device speedup claim. Interpreted arithmetic falls from
3,603 to 2,175 evaluations with 39 trace events in each version; both pass the
independent conflict/order oracle.
