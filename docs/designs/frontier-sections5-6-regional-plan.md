# Sections 5–6: regional fallback and reusable certificates

Baseline: `4710959d9`. Status: M1–M2 accepted; M3–M5 remain open.

The implementation preserves exact minimum demands, original cuts, matching and
established realization guarantees on exact paths. Completion fallback reports
coverage and possible added order. An exact mathematical answer with a missing
export never authorizes weakening that answer.

## Reviewed implementation sequence

1. **Regional completion ownership:** separate proper-region pending summaries
   from whole-invocation completion; import eligible retained inline children and
   existing qualified calls atomically; reuse the SCC engine and module staging.
2. **Completion inputs and guarantees:** hierarchy-wide proved storage classes,
   qualified forward scalar readiness, explicit conservative guarantees and
   optional symbolic payload-order loss bounds.
3. **Periodic/repeated certificates:** preserve modular boundary selectors and
   numerical indices; qualify supplied phases without arbitrary period search;
   close the phased-repeat watchdog using its independent oracle.
4. **Bounded lifetimes:** share rotating normalization, derive collective refresh
   gaps from guaranteed writers, retain one certified window across exports.
5. **Arithmetic construction contracts:** retain normalized whole-primitive
   certificates and report actual projection/subtraction/export strategy costs;
   preserve cheap representations through qualifying composition.

Each milestone includes production callers, semantic and structural scaling
checks, a deletion ledger, two independent reviews and one accepted commit before
starting the next. Reuse incremental builds; at most two aggregate heavy workers.
Do not push automatically. The final gate includes Frontier tests and the 49
primary PyPTO-lib modules; report the broader legacy gate separately. Three serial
interleaved timing pairs measure affected fixtures; neutral results remain valid.

## Scope decisions

Use existing Empty, CompletedExit and ClosedDescendants resource contracts. New
pending children owning local events, coordinator protocols, protocol synthesis,
runtime dependence analysis and device qualification are excluded. Start with
the qualified A3 single-core ALL-barrier protocol. An ALL barrier does not consume
outstanding notifications. Unsupported history, resources or readiness remain
unmet capabilities. No new public pass, solver or arbitrary admission cutoff.

Proper regions are contiguous original structural intervals; macro envelopes are
indivisible. Empty and zero-trip children pass incoming pending work through.
While summaries include the final false condition visit. Child effects, matching
closure and completed payloads are separate facts. Imported exact code is retained,
not reconstructed by the conservative solver.

## M1 implementation and deletion ledger

Implemented and accepted by architecture and compiler-correctness reviewers.
The [M1 receipt](frontier-sections56-m1-results.json) records source hashes and tests.

The completion graph accepts contiguous original roots and qualified inline child
implementations. Proper regions retain pending suffixes and transparency; only a
whole invocation adds its terminal drain. Proper owners are append-only fragments,
not standalone function transformations. A whole owner stages their retained
recipes and boundary completions in the existing module transaction.

Inline finite import currently admits no-notification recipes: exact local
barriers and their certified scalar preparation. Existing call imports retain
Empty, CompletedExit and ClosedDescendants contracts. An eventful inline result
without supported closure evidence remains unselected; its mathematical result
is retained, and the parent can descend through that candidate. Once a child is
accepted, failed revalidation aborts the parent transaction. Neither an exact
demand result nor a visible ALL establishes notification closure.

A source snapshot validates the shared input/index association once, retains the
original function/module identity and immutable phase facts, and is shared across
session scopes. Staging validates each distinct source and imported callee once.
Scope inspection reports actual operation/phase visits and graph vertices.

The regional straight-line adapter already retains a finite owner inside its
singleton sequence result. Fallback retrieves that owner; it does not reconstruct
finite mathematics or add a separate regional finite adapter.

## M2 implementation and deletion ledger

Implemented and accepted by architecture and compiler-correctness reviewers.
The [M2 receipt](frontier-sections56-m2-results.json) records source hashes and evidence.

Completion source snapshots now own one deterministic storage-class universe for
all proper scopes. Classes distinguish proved address spaces and disjoint local
physical reservations. Overlapping or adjacent reservations are merged; every
address-table alternative participates. Missing addresses, zero/overflowing
extents and lost provenance conservatively cover the entire space. Unknown
spaces cover all classes. GM remains coarse. Unknown memberships retain ranges,
not copied class inventories. Empty and call-only functions have at least one
class. Dense graph summaries still cost O(vertices × classes); this is not an
end-to-end linearity claim.

Finite inline effects use that same classifier. Proper completion children share
the full input's deterministic numbering, including across source snapshots.
Callee exports remain deliberately coarse: collapse and lift A, E and S separately
and preserve transparency. Callee-local reservations never become caller class
identities without argument-substitution evidence.

A qualified scalar prerequisite stays within one original block and visit.
Completion precedes the earliest direct scalar use, including intermediate pure
arithmetic; the final payload consumer is not used as a substitute for that cut.
Control, carried, escaping and externally sourced obligations remain unavailable.
An accepted atomic child hiding a mandatory cut is refused. Readiness discovery
reports operation and use visits separately. Integration tests inject an
asynchronous contract into test-owned input phases; production tgetval remains
synchronous and its ISA semantics are unchanged.

The result reports covering modeled order, SCC placement, actual class count,
readiness cuts, retained inline children, zero parent event IDs and separate
matching/payload-completion semantics. The optional realized-order loss bound
remains explicitly unavailable, never zero. Existing child-resource restrictions
remain unchanged.

| Previous adapter | Replacement | Removal status |
|---|---|---|
| One-class primitive effect assembly | Snapshot-owned CompletionStorage | Removed |
| Direct copy of callee class numbering | Coarse A/E/S collapse and caller lift | Removed |
| Blanket nonnative scalar-result refusal | Same-block first-use readiness certificate and mandatory SCC entries | Unsupported forms still explicitly refused |
| Implicit single-class completion metadata | Explicit storage/readiness/child guarantee fields | Replaced |

M2 qualification passes 12/12 focused tests, including storage overlap oracles,
first-use insertion, separate-snapshot class compatibility and threaded production
output. Public disjoint/wildcard fixtures scale through 512 classes. Three serial
interleaved immediate-M1 timing pairs are neutral: candidate/baseline medians
1.013, 1.019 and 0.998 for disjoint256, wildcard256 and while control. Disjoint256
reduces ALL barriers from 256 to one invocation drain; wildcard256 reduces 257
to two. These are conservative-order improvements, not device-speed measurements.
