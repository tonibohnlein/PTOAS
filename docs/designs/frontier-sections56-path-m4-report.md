# M4 — Pending executable children in regional completion

Baseline: `a9ac99b52` (accepted M3). This completes the qualified M4 production
path in the [plan](frontier-sections56-path-completion-plan.md). The
[machine-readable receipt](frontier-sections56-path-m4-results.json) records the
focused gate, tool/input hashes and three interleaved timing pairs.

## Contract and implementation

The existing finite provider can export a concrete singleton direct fragment
with closed logical matching per visit and an ordinary finite within-visit
assignment. Enclosing counted-loop coordinates distinguish visits. These children
can still return pending payloads: their imported summary is E=S=A, t=true.
Closed matching is not a completed-payload or consumed-notification certificate.
Guarded early publication, terminal cleanup, private state and eventful children
under while loops remain outside this new export contract.

After the unchanged SCC transfer selects storage/readiness completions, a
separate two-state traversal follows clean/pending notification state over the
original CFG. Every subsequent eventful child or call requires a clean state.
Only an original ALL or an already-selected completion clears that state.
The child has issued all matching WAITs; ALL establishes their completion. It
does not consume an unmatched flag. Proper regions retain pending resource exit
state, while the existing whole-invocation return completion closes it.

If resource separation is unavailable, these provisional eventful imports are
removed and the existing primitive completion construction is retried once.
This does not preserve the rejected child's exact protocol, and does not mutate
previously issued owners. No completion is inserted solely to qualify resources.
Both the provisional graph work and retry work remain accounted for.

Child code uses the existing family materializer, insertion and regional-palette
allocator. Incremental record numbering and palette accumulation replace scans
of all earlier imports; namespace normalization occurs once. Within-child
conflicts retain directional lane separation. Cross-child reuse depends on the
parent CFG certificate. Requested eligible IDs are assigned by the ordinary
physical pass, with insufficient capacity remaining a separate refusal.

Readiness now admits indirect branch prerequisites when their actual same-block
first scalar use is protected and dominates each dependent target. Carried,
escaping and unavailable provenance remain unsupported. This changes no storage
may-alias rule.

## Qualification and scope

The fresh focused gate passes 11/11. Independent logical/physical checks cover
12 zero/skipped/nested counted visits, final-false while-condition payloads,
within-child order equality, complete storage coverage, matching and causal
reuse. The nondefault pool is {2,5}; a one-ID request refuses without output.
No-ALL and bypass-ALL inputs reject provisional imports; an unconditional
existing ALL permits them. A separate test retains an inline SET before a
precompiled closed child, requires the selected ALL immediately before the call,
preserves the callee byte-for-byte and performs physical allocation.

The trace interpreter now executes the final false while condition. Its existing
visit/event limits remain in force. The independent allocation oracle includes
ALL in causal closure, but occupancy is still cleared only by actual WAITs.

Geometric production tests retain 8/32/128 children through physical allocation.
They emit N SET/WAIT sites, N+1 ALL sites, and at most 2N+8 arithmetic operations.
The resource proof processes at most two states per graph vertex per attempt;
this is a construction bound, not a claim that the complete regional dispatcher
is linear. Three interleaved timing pairs show candidate/baseline ratios of
1.007 for the nested case and 1.012/1.008/1.042 for 8/32/128 children. There is
no speedup claim. The new protocol preserves selected exact children: the
128-child case changes 256 ALL sites into 129 ALL plus 128 matched pairs.

Saved/reparsed logical output and ordinary allocation are supported. Combined
physical-output completion owners remain explicitly unavailable and tested as
such. General eventful guarded children, history-dependent cleanup and arbitrary
call/loop resource lending are not newly admitted.

During development a detached-block OpBuilder constructor caused a crash in the
new append path. Constructing the builder from its context before setting the
detached insertion point fixes it; the final gate exercises that path. The first
call fixture also failed because its unsplit explicit run included the unsupported
call; the corrected fixture supplies a real contiguous inline child boundary.
No existing semantic expectation or watchdog was relaxed.

Architecture and correctness reviews accept the source and require the final
11/11 gate, which passes. Incremental builds pass without new compiler warnings.
The changed-code prefilter's brace matches were inspected: the bodies are braced;
its nested-call/multiline-condition regex produces false positives. Line-length
findings were fixed. No suppression, device run or full-corpus result is claimed
by this milestone; those final compiler gates remain M5 obligations.
