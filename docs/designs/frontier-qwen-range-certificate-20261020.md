## Implementation

Facts travel in the existing typed expression DAG. Regional composition already retains the normalized count and guarded phase expressions; this change derives their ranges at the certificate consumer. It introduces no detached fact owner, caller registry, backend or admission cutoff.

- `Shared/RegionIntervalProof.cpp` uses LLVM 19 `ConstantRange` for conservative 64-bit ranges of constants, Boolean values, wrapping add/subtract, unsigned division/remainder and selections. A selection refines an arm only when that arm is the compared operand and the other operand is constant. Unsupported values remain full-range. A divisor range containing zero is not used to infer a division/remainder range.
- `RegionExpressions::impliesByIntervals` proves a sufficient implication by refuting `premise && !consequence`. The existing threshold specialization is extended, on this explicit certificate path, to comparisons of a shared derived integer expression. Its unconditional range is partitioned into exact cells; other inputs stay unconstrained. No Cartesian product of input valuations or runtime visits is constructed.
- `Shared/RegionalLaneCertificate.cpp` requests that proof after the existing cheap checks fail. It caches Boolean results only within the current unchanged arena/certificate request. Every present last-target/first-source pair must still qualify. Terminal-cleanup exclusions remain intact.
- Ordinary `inactiveByThresholds` callers retain their direct-input path. Extra derived families and range facts are prepared only for the new proof request. Range facts are proof-local; immutable source topology/dependency caches retain existing rollback handling.

No original SSA is evaluated or generated by the proof. It neither replays an unavailable condition nor emits a synchronization calculation. Caller facts matter only when already explicitly reflected in the supplied expressions/premises. In particular, an arbitrary integer input is not assumed nonnegative, and an unconstrained normalized count is **not** assumed at most eight.

### Validity argument

For a derived integer value `v`, range transfer returns an enclosure of every possible defined machine-bit value. Wrapped sets may lose precision when converted to an unsigned hull; they are never narrowed to a convenient signed half. Selection refinement follows the actual comparison and branch, with signed boundaries handled by LLVM's comparison regions.

The proof partitions that complete enclosure. Within each cell, existing specialization folds only comparisons constant throughout the cell, retaining modular wrap, the signed cut and exact refinement points. Treating `v` atomically loses correlations with its operands; it assumes no inverse. Other occurrences of those operands remain unconstrained. If the refutation is false in every cell, it is false for every actual value of `v`. An unsupported proof stays unproved.

For the diagnosed Qwen circuit, signed clamping bounds the distance before divide/round. The resulting count `T` is nonnegative and below the signed cut. Consequently `min(T,0)=0`, `min(T,1)` has range 0–1, and the lane-12→24 activity supplies `T≥2`. The query circuit can be specialized under those facts without assuming K=17 or enumerating K.

The proof is sufficient, not a complete arithmetic decision procedure. Ranges that remain full, unrelated values, unsupported operations and unresolved implications retain refusal. No guarded successor relation is transitively closed.
